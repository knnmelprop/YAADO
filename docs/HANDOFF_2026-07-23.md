## 3. THE KEY FINDING — the identity question is mis-framed

`marker_zones.yaml.template` asks which solid is the ramjet stage and which
is the booster. **The geometry says that question has no answer as posed.**

| | vol_1 | vol_2 |
|---|---|---|
| X range (mm) | 30.13 – 1071.51 | 159.81 – 4385.15 |
| Length (mm) | 1041.38 | 4225.34 |
| Max radius (mm) | ~105.3 | ~296.5 |

- **vol_1's outer max radius = 105.33mm. vol_2's forward bore radius =
  104.4–108.5mm.** Same radius — **vol_1 nests INSIDE vol_2** through the
  whole overlap zone x=[159.8, 1071.5]mm.
- **vol_2 spans 4225mm of the 4355mm vehicle** and carries the fins.
- vol_1 tapers to a ~7.6mm-radius near-sharp tip at x=50mm, and is ~147mm
  diameter at x=200mm (cf. config `nose_diameter_m: 0.150`).

So this reads as **inner centerbody/spike (vol_1) inside an outer
airframe-with-duct-and-fins (vol_2)** — NOT stage-1 vs stage-2.

**Do not fill `marker_zones.yaml` with a solid→stage mapping.** It would
encode a false premise into the file that gates all downstream meshing, and
a wrong marker assignment does not fail loudly — it silently corrupts the
static-margin *sign*, which is the entire deliverable.

The X-range-based marker scheme still works. The ranges must come from real
geometric transitions — which are now measured (§4).

## 4. Measured geometry (two independent runs agree)

Data: `analyses/geometry/results/station_sweep_topology_2026-07-23.csv`
and `..._transitions_2026-07-23.csv` (both tracked).

The 7-station topology run was executed **twice independently** (coordinator
and a subagent) and produced **byte-identical** results.

### Confirmed features
- **Internal bore exists x≈160 → 2400mm.** `n_loops=2`. Bore radius
  ~108.5mm (x=200), 104.4 (500), 108.1 (1000), 60.6 (2000), 56.5 (2400).
- **Bore CLOSES between x=2400 and x=2500mm.**
- **Uniform barrel x=2500 → 3600mm**: area identical to 10 sig-figs
  (12667.686977437404 mm²), r_eq 63.50mm, outer_bbox_r 65.00mm.
- **Fins BEGIN between x=3600 and x=3800mm**: outer_bbox_r goes
  65.00 → 163.33 → 296.53mm (x=4000). `n_loops=1` throughout (blades, not
  holes — this was the ambiguity the loop-topology work resolved).
- **vol_1 is solid** (`n_loops=1`) at every station probed.

### Two flagged anomalies — NOT interpreted, for human review
1. **x=2100mm: 14 separate small faces**, each ~56.5mm² (r_eq 4.24mm), at
   bbox radii ~62–65mm — a ring of 14 small circular members at the duct
   wall radius. Reads like a strut/vane/pin ring or perforated station.
2. **Barrel outer diameter measures 130.0mm** (2 × 65.0mm), but
   `vehicle_config.yaml` `body.diameter_m` is **0.200 (200mm)** — a **70mm
   discrepancy** on a field marked drawing-verified. **Unresolved. No config
   value was changed.**

### Incidental evidence on the open fin-span question
Fin tips reach r=296.5mm → **tip-to-tip ≈ 590mm**. Config offers
`fins.span_m: 0.550` (550mm, "MODERATE CONFIDENCE") and
`body.max_diameter_m: 0.639` (639mm, "needs review"). Measured 590mm falls
between and matches neither. Real third data point; not a verdict.

### Cost model (corrected — important)
**~35–73 s/station** with loop topology, NOT the ~8.4 s/station quoted in
`status.md` §4b (that figure timed slicing *without* the topology walk).
**A 220-station 20mm-pitch full sweep is ~4.5 hours, not ~31 minutes.**
The STEP merge alone is 30–224 s. Use targeted ranges.

## 7. Standing environment gotchas (hard-won — do not rediscover)

- **pipefail trap:** `cmd | tee log | tail -N` reports `tail`'s exit code,
  not `cmd`'s. A build once reported "exit code 0" while actually failing.
  Use `set -o pipefail`, or capture `$?` with no trailing pipe.
- **`python` does not exist**, only `python3` (Homebrew python@3.14).
- **PEP 668:** `pip install --user` is blocked. Use a venv.
- **Homebrew's `gmsh` CLI does NOT ship Python bindings.** The PyPI `gmsh`
  module must be installed separately at the same pin (4.15.1). Existing
  venvs: `analyses/geometry/.venv-geom/`, and the SU2 case's `.venv-gmsh`.
- **The STEP file is gitignored** (14MB). Cloud/remote sessions will NOT
  have it — any real-geometry work must run locally. This is exactly why the
  tool sat synthetic-only for a session.
- **`.gitignore` ignores `*.cfg` and `*.su2` globally**, deliberately.
  Tracked configs are `*.cfg.template`; live configs generate into
  gitignored dirs.
- **Single working tree:** parallel agents must not `git checkout` — it
  yanks the tree out from under whatever else is running. Two agents were
  run concurrently this session only because one was confined to `runs/`.
